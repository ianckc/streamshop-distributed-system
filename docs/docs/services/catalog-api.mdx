# catalog-api

Node.js HTTP service for the product catalog.

## Status

| Feature | Status |
|---------|--------|
| `GET /health` | Implemented |
| `GET /ready` | Implemented |
| `GET /api/catalog/products` | Implemented |
| `GET /api/catalog/products/:id` | Implemented |
| MongoDB persistence | Implemented |
| Redis cache-aside | Implemented (60s TTL; fail-open) |
| MinIO image URLs | Implemented (presigned GET; `{id}.png`) |
| MinIO image upload | Planned |
| Nginx replicas | Implemented (2 behind nginx, round_robin) |

## Stack

| | |
|--|--|
| Language | Node.js 22 + TypeScript |
| HTTP | Fastify 5 |
| Database | MongoDB 8 via official driver |
| Cache | Redis 8, cache-aside |
| Objects | MinIO (`product-images`) |
| Port | `3001` (replica 1; replica 2 is `3011`) |

## Run with Docker Compose

From the repository root:

```bash
cp .env.example .env   # optional
docker compose up --build
```

Starts **Traefik**, **nginx**, **mongo**, **redis**, **redisinsight**, **minio**, **redpanda**, **redpanda-console**, **postgres**, **order-api**, **catalog-api-1**, and **catalog-api-2**. Health/ready: `http://localhost:3001/health` (replica 1) and `http://localhost:3011/health` (replica 2). Products via Traefik → nginx: `http://localhost:8080/api/catalog/products`.

## Endpoints

### `GET /health`

Liveness check.

```bash
curl http://localhost:3001/health
```

```json
{"status":"ok","service":"catalog-api-1"}
```

Replica 2 is the same on `:3011` with `"service":"catalog-api-2"`. Every response also has `x-replica-id`.

### `GET /ready`

Readiness check: pings MongoDB. Use this to decide if the instance can serve traffic. Compose still healthchecks `/health` (process up).

```bash
curl http://localhost:3001/ready
```

```json
{"status":"ok","service":"catalog-api-1"}
```

Mongo unavailable → `503` `{"error":"not ready"}`.

### `GET /api/catalog/products`

Returns the product catalog from MongoDB (`products` collection), with Redis cache-aside (`catalog:products`, TTL 60s). Amounts are in **pence**. When `product-images/{id}.png` exists in MinIO, the item includes a presigned `image_url` (1 hour, host rewritten to `localhost:9000`). MinIO down or missing object → product JSON without `image_url` (fail-open). First request after a miss sets `x-cache: miss`; the next request within the TTL is `x-cache: hit`. Traefik → nginx round-robins replicas; `x-replica-id` shows which one served the request. Redis unavailable → serve Mongo and still return 200 (`x-cache: miss`). `/ready` still pings Mongo only.

```bash
curl http://localhost:8080/api/catalog/products
```

```json
{
  "products": [
    {
      "id": "prod-001",
      "name": "StreamShop Mug",
      "price_pence": 1999,
      "attributes": { "colour": "navy", "material": "ceramic" },
      "image_url": "http://localhost:9000/product-images/prod-001.png?X-Amz-Algorithm=..."
    }
  ]
}
```

`id` values match `product_id` on `POST /api/orders` (e.g. `prod-001`). In Mongo the public id is stored as `_id`. `attributes` is a free-form string map. `image_url` is omitted when there is no object. Redis caches the Mongo document only; presigned URLs are attached after the cache.

Mongo unavailable → `503` `{"error":"failed to list products"}`.

### `GET /api/catalog/products/:id`

Returns one product. Same JSON shape as an item in the list. Cached at `catalog:product:{id}` (TTL 60s). 404s are not cached.

```bash
curl http://localhost:8080/api/catalog/products/prod-001
```

```json
{
  "id": "prod-001",
  "name": "StreamShop Mug",
  "price_pence": 1999,
  "attributes": { "colour": "navy", "material": "ceramic" },
  "image_url": "http://localhost:9000/product-images/prod-001.png?X-Amz-Algorithm=..."
}
```

| Status | When |
|--------|------|
| `404` | Unknown id |
| `503` | Mongo unavailable |

### Inspect Mongo

```bash
docker compose exec mongo mongosh streamshop --eval 'db.products.find().pretty()'
```

Seed data is loaded from `infra/mongo/seed.js` on first start of an empty volume. Reset with `docker compose down -v`.

### Inspect Redis

```bash
docker compose exec redis redis-cli ping
docker compose exec redis redis-cli GET catalog:products
```

Redis Insight (local GUI, not behind Traefik): [http://localhost:5540](http://localhost:5540). Hit list or detail once, then inspect `catalog:products` and `catalog:product:prod-001`.

### Inspect MinIO

MinIO console (not behind Traefik): [http://localhost:9001](http://localhost:9001) (`streamshop` / `streamshop`). S3 API: `http://localhost:9000`. Object key for a product is `{id}.png` in `product-images`. Catalog list/detail return a presigned `image_url` when that object exists. Upload via the API is not wired yet.

```bash
curl -sI http://localhost:9000/minio/health/live
curl -s http://localhost:8080/api/catalog/products/prod-001 | jq .image_url
```

## Configuration

| Variable | Default | Description |
|----------|---------|-------------|
| `PORT` | `3001` | HTTP listen port |
| `SERVICE_NAME` | `catalog-api` | Shown in health/ready JSON and `x-replica-id` (Compose uses `catalog-api-1` / `catalog-api-2`) |
| `MONGODB_URI` | *(required)* | MongoDB connection string |
| `REDIS_URL` | *(required)* | Redis connection string |
| `S3_ENDPOINT` | *(required)* | MinIO/S3 API URL (Compose: `http://minio:9000`) |
| `S3_PUBLIC_ENDPOINT` | `http://localhost:9000` | Host rewritten into presigned URLs |
| `S3_ACCESS_KEY` | *(required)* | MinIO root user |
| `S3_SECRET_KEY` | *(required)* | MinIO root password |
| `S3_BUCKET` | `product-images` | Image bucket |
| `S3_REGION` | `us-east-1` | Required by the AWS SDK; unused by MinIO |

## Local development (without running the app in Docker)

```bash
docker compose up -d mongo redis minio minio-init
cd services/catalog-api
cp .env.example .env
npm install
npm start
```

`MONGODB_URI`, `REDIS_URL`, and `S3_*` in `.env.example` point at `localhost`. Inside Compose the hostnames are `mongo`, `redis`, and `minio`.

## Tests

```bash
npm test
npm run test:coverage
npm run lint
```

`npm run lint:fix` applies Biome format and lint fixes. Handler tests use an in-memory fake store, cache, and image store — no Mongo, Redis, or MinIO required. Coverage is printed in the terminal; HTML is written to `coverage/index.html`. Excluded: `src/server.ts` (process entrypoint) and type-only modules. `src/store/mongo.ts` stays in the report at 0% until Mongo is tested (mock or Testcontainers). `src/cache/redis.ts` `connectRedis` is untested; `RedisProductCache` is covered with a fake client. `src/images/s3.ts` is untested against MinIO (unit tests use the in-memory image store).
