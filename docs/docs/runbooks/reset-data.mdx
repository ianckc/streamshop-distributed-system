# Reset Data

Use this runbook to wipe all local data and re-seed the system with fresh sample data.

## When to use

- Demo preparation before an interview
- Recovering from a corrupted local state
- Testing the seed script after schema changes

## Steps

### 1. Stop all services

```bash
make down
```

### 2. Remove volumes

```bash
docker compose down -v
```

This deletes all Postgres, MongoDB, Redis Insight, MinIO, Redpanda, and ClickHouse data.

### 3. Restart and seed

```bash
make up
make seed
```

The seed script (`scripts/seed.sh`):

- Upserts sample products into MongoDB (`prod-001` … `prod-003`)
- Ensures Redpanda topics (`orders.events`, `orders.events.dlq`)
- Uploads sample product images to MinIO (`infra/minio/sample-images/`)
- Flushes the Redis catalog cache

There is no users table; orders take a `user_id` UUID in the request body. Mongo also seeds from `infra/mongo/seed.js` on first start of an empty volume.

### 4. Verify

```bash
make smoke
```

Expected output: catalog list includes `prod-001`, a sample order is created as `pending`, status becomes `processed` within 10 seconds, and `/api/analytics/orders/summary` reports `order_count >= 1`.

## Reset a single datastore

| Store | Command |
|-------|---------|
| PostgreSQL | `docker compose exec postgres psql -U streamshop -d streamshop -c 'TRUNCATE outbox, orders, order_items CASCADE'` |
| MongoDB | `docker compose exec mongo mongosh streamshop --eval 'db.products.deleteMany({})'` |
| ClickHouse | `docker compose exec clickhouse clickhouse-client --user streamshop --password streamshop --database streamshop -q 'TRUNCATE TABLE order_events'` |
| Redis | `docker compose exec redis redis-cli FLUSHALL` |
| MinIO | `docker compose exec minio mc rm --recursive --force local/product-images/` |

After a partial reset, run `make seed` to restore sample catalog data and images.

## Apply Postgres schema changes (existing volume)

Postgres runs `infra/postgres/init.sql` only when the `postgres_data` volume is **empty** (first container start). If you already have local data and a new migration is added (for example the transactional `outbox` table), either wipe and recreate or apply the incremental script.

**Wipe all data** (simplest for demos):

```bash
docker compose down -v
make up
make seed
```

**Keep data** — apply the migration script from the repo root:

```bash
docker compose exec -T postgres psql -U streamshop -d streamshop < infra/postgres/outbox.sql
```

Verify:

```bash
docker compose exec postgres psql -U streamshop -d streamshop -c '\d outbox'
```
