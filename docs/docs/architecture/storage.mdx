# Storage

StreamShop uses distinct storage technologies, each chosen for a specific access pattern.

## Storage map

| Store | Type | Technology | Primary data |
|-------|------|------------|--------------|
| PostgreSQL | SQL (OLTP) | PostgreSQL 18 | Orders, order items |
| MongoDB | NoSQL | MongoDB 8 | Product catalog (flexible schema) |
| ClickHouse | OLAP | ClickHouse 24 | Order event facts, aggregates |
| MinIO | Object | MinIO (S3-compatible) | Product images, CSV exports |
| Redis | Cache | Redis 8 | Hot reads, idempotency keys |

## PostgreSQL (OLTP)

Relational storage for transactional order data.

```sql
CREATE TABLE orders (
  id          UUID PRIMARY KEY,
  user_id     UUID NOT NULL,
  status      TEXT NOT NULL DEFAULT 'pending',
  total_pence INTEGER NOT NULL,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE order_items (
  order_id    UUID REFERENCES orders(id),
  product_id  TEXT NOT NULL,
  qty         INTEGER NOT NULL,
  price_pence INTEGER NOT NULL
);
```

**Accessed by:** `order-api` (writes), `event-processor` (status updates), `analytics-api` (detail reads)

## MongoDB (NoSQL)

Document store for the product catalog. Products have variable attributes — colour, size, material — that don't fit a rigid relational schema.

```json
{
  "_id": "prod-001",
  "name": "Running Shoes",
  "price_pence": 8999,
  "attributes": {
    "colour": "blue",
    "size": ["8", "9", "10"],
    "material": "mesh"
  }
}
```

**Accessed by:** `catalog-api` (reads list and detail today; writes planned)

Seed documents live in `infra/mongo/seed.js` and load on first start of an empty volume.

## Redis (Cache)

In-memory cache for hot catalog reads and (later) order idempotency keys. Redis is **not** a primary datastore — Mongo remains the source of truth. There is no Compose volume; cache is ephemeral by design.

**Today:** Redis 8 runs in Compose on `:6379` (no password). catalog-api sets `REDIS_URL` but does not read or write Redis yet. Cache-aside is the next catalog slice. See [Caching](./caching).

```bash
docker compose exec redis redis-cli ping
```

Browse keys in Redis Insight at [http://localhost:5540](http://localhost:5540) (local debug GUI; not behind Traefik).

## ClickHouse (OLAP)

Columnar analytics store for denormalized order event facts.

```sql
CREATE TABLE order_events (
  order_id     UUID,
  user_id      UUID,
  total_pence  UInt32,
  item_count   UInt8,
  event_time   DateTime,
  processed_at DateTime
) ENGINE = MergeTree()
ORDER BY (event_time, order_id);
```

Materialized views power hourly revenue aggregates queried by `analytics-api`.

**Accessed by:** `event-processor` (writes), `analytics-api` (reads)

## MinIO (Object storage)

S3-compatible object storage for binary assets.

| Bucket | Contents | Access |
|--------|----------|--------|
| `product-images` | Product photos | Presigned GET URLs |
| `exports` | CSV analytics exports | Internal only |

**Accessed by:** `catalog-api` (upload), `analytics-api` (export, optional)

## Why not one database?

| Pattern | Wrong tool | Right tool |
|---------|-----------|------------|
| Flexible product attributes | Postgres JSONB (works, but awkward) | MongoDB documents |
| Hourly revenue rollups | Postgres aggregation (slow at scale) | ClickHouse columnar scans |
| Product image blobs | Postgres BYTEA (expensive, wrong abstraction) | MinIO object storage |
| Order transactions | MongoDB (no ACID across documents) | PostgreSQL |

See individual ADRs for detailed rationale: [ClickHouse](../adr/clickhouse-for-olap), [MongoDB](../adr/mongo-for-catalog).
